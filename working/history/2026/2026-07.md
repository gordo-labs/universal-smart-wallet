# History — July 2026

## 2026-07-29 — Project conception and orchestration scaffold

Created the project control layer, feasibility review, technical and product
maps, feature boundaries, threat assumptions, roadmap, and atomic construction
graph from the owner-supplied prompts.

The review corrected four material assumptions: SD-JWT VC is not final,
ERC-7579 is not final, selective disclosure is not a general predicate proof,
and passkeys do not universally expose encryption key material. The resulting
plan uses versioned adapters, a derived age claim, and a vault key-management
spike with non-PRF recovery behavior.

No product code, GitHub repository, deployment, or release was created.

## 2026-07-29 — Public planning repository

With explicit owner approval, created the public repository at
`https://github.com/gordo-labs/sovereign-smart-wallet` and pushed the reviewed
planning commit `f1fd664` to `main`.

Added planning CI and Dependabot configuration, enabled GitHub security
features, and documented the public reporting path. This publication is not a
product release. `SSW-002` remains in progress until `SSW-001` provides the
executable root checks that CI must mirror.

## 2026-07-29 — SSW-001 executable foundation

Bootstrapped a pinned pnpm/Node TypeScript monorepo with three network-free app
shells, typed package boundaries, root validation scripts, and a local Foundry
harness. No credentials, remote services, or production contracts were added.

## 2026-07-29 — SSW-002 CI and governance alignment

Updated `.github/workflows/planning.yml` to run the executable root checks from
`SSW-001`: toolchain validation, frozen install, lint, typecheck, unit tests,
build, e2e smoke, and Foundry tests, with pinned GitHub Action SHAs. Verified
the public repository, active workflows, protected `main`, secret scanning and
push protection, Dependabot/security alerts, and private vulnerability
reporting through `gh`. No release, deployment, hosted service, or secret was
introduced.

## 2026-07-29 — SSW-003 standards and dependency baseline

Re-checked official OpenID, IETF, W3C, Ethereum, Safe, and WebAuthn sources.
Recorded exact final/draft revisions, candidate package versions with license
and replacement notes, browser/chain limitations, and the EntryPoint 0.8.0

## 2026-07-29 — SSW-006 vault key-management boundary

Accepted the versioned AES-GCM envelope and explicit PRF/HKDF or PBKDF2
wrapping strategies. Added WebCrypto capability detection, deterministic
round-trip/tamper/migration vectors, bounded KDF parameters, and threat-model
consequences for loss, sync theft, and rollback. No passkey signature,
plaintext factor, IndexedDB adapter, or external service was introduced.

## 2026-07-29 — SSW-015 smart-account selection and harness

Confirmed SSW-003 at `d831f9e`, compared Safe and Kernel, and selected Safe
Protocol Kit `8.0.4` behind a narrow account adapter. Added the ADR, pinned
EntryPoint/deployment manifest, metadata validation, and a deterministic local
Foundry harness. The harness uses test-only external bytecode and stores no
credentials or assets; no passkey UI, UserOperation, module, recovery, hosted
provider, or testnet deployment was added. Branch:
`docs/SSW-015-smart-account-adr-foundry`.

## 2026-07-29 — SSW-016 local passkey account and ERC-1271

Added a WebAuthn assertion boundary with exact context checks, explicit
cancellation/unavailable errors, external P-256 verification, deterministic
public-input account derivation, and local ERC-1271 positive/negative tests.
Validation passed for adapter tests (10), wallet build, and Foundry (5 tests).
Playwright/cross-browser checks remain deferred because no browser harness is
present yet. No custom account, recovery, ERC-4337, or ERC-7579 feature added.

## 2026-07-29 — SSW-007 encrypted vault and IndexedDB adapter

Added authenticated AES-GCM envelope metadata, bounded credential indexes,
in-memory and IndexedDB storage adapters, atomic replacement migrations,
deletion, and recoverable corruption errors. Tests use WebCrypto and a
dependency-free fake adapter; no plaintext credentials or external services.
